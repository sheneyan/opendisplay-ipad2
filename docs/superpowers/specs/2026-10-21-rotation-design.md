# Automatic orientation for legacy iPads

**Superseded:** the user approved manual Rotate 90° instead. See the manual-rotation design/plan dated October 21, 2026. This document preserves the failed automatic-orientation trial.

The user approved adding automatic landscape/portrait display rotation to both existing clients, preserving desktop/video presets, touch controls and the mini settings hold. Build 10 follows UIKit's interface orientation (and its rotation lock), swaps every desktop/panel/video dimension pair for portrait, and sends a new pv3 hello after a debounced sleep/wake session recreation. An orientation change cancels any gesture and releases a held mouse button before retiring the old session. Input from the old geometry/session is rejected; new input waits for matching video orientation. The decoder already rebuilds on changed SPS/PPS.

Keep saved presets as landscape long-edge widths. The mini settings page presents them in the current orientation without changing preferences. Both landscape directions and both portrait directions are allowed. A 180-degree turn only rotates UIKit; it does not change the virtual desktop dimensions. No network transport, codec, audio or other gesture features are added.

Validation covers portrait fields and return to landscape, connected and offline orientation changes, identity continuity and deliberate session replacement, stale input suppression, actual decoded portrait video, real taps/scrolling and mini settings after rotation. Both device packages remain separate and Build 8 packages are retained locally. The capability comparison is pinned to the installed Mac sender version 1.19.0 and distinguishes implemented, protocol-only and unverified behavior.

## Evidence-driven compatibility correction

Build 9 used live hello updates. On the actual 1.19.0 sender, rotation produced 1920×2560 video on iPad 2 instead of 768×1024, and 2400×3200 on mini instead of 1536×2048. The user observed a centered small image and delayed black-screen recovery. Recreating the iPad 2 session while retaining portrait restored the advertised ceiling and a full-screen image. The official sender source confirms that initial setup applies the ceiling while its in-place resize path omits it. Build 10 therefore sends sleeping and closes the old stream after 0.6 seconds of settled orientation; the sender's wake-waiting replacement reconnects to the still-running listener. New connections accepted during the debounce are not retired by stale timers. This trades interruption and possible window relocation for correct initial stream dimensions. Mini 2 testing measured approximately 9 seconds from session retirement to capture restart, which the user considered too long. Sender capture reattachment also omits the ceiling, so this workaround does not close every recovery path. iPad 2 had no noticeable black-screen interruption according to the user; mini rotation remains unresolved.
